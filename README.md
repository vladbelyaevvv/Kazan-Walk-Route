# Прогулочные маршруты по центру Казани

Веб-приложение для подбора прогулки по каталогу из 32 мест центра Казани. Пользователь выбирает старт и свободное время, получает два варианта маршрута и сравнивает их на карте.

Стек: React, TypeScript, Vite, Leaflet и OpenStreetMap. Пешеходные расстояния и геометрия пути запрашиваются у Valhalla.

## Запуск

Требуется Node.js 20.19 или новее.

```sh
npm ci
npm run dev
```

Открой локальный адрес, который напечатает Vite. Для карты и загрузки маршрутов нужен интернет.

## Сборка и проверки

```sh
npm test
npm run typecheck
npm run build
npm run preview
```

В Windows PowerShell при ограничении запуска `npm.ps1` можно использовать `npm.cmd` вместо `npm`.

## Как пользоваться

1. Выбери длительность: 1, 1,5, 2, 3 или 4 часа.
2. Укажи старт в списке или карточке места на карте.
3. Оставь исходные настройки — скорость 5 км/ч, остановка 10 минут, соседство зон 12 минут — либо измени их.
4. Нажми «Сравнить два маршрута». При первом запуске приложение загружает матрицу переходов и сохраняет её в браузере.
5. Переключай карточки вариантов, чтобы посмотреть остановки, время, длину и путь на карте. Результаты можно выгрузить в JSON или CSV.

## Чем отличаются варианты

Базовый способ выбирает ближайшее непосещённое место, на переход и осмотр которого хватает времени.

Зональный способ сначала ищет место в текущей тематической группе, затем в соседней непосещённой группе. Если подходящих вариантов нет, он выполняет общий поиск, допускающий возвращение в ранее посещённую группу. Зоны — группы объектов каталога, а не административные районы.

Оба способа учитывают время ходьбы и остановок. Старт считается посещением; возвращение к старту после последней остановки не включено. Ни один способ не гарантирует оптимальный маршрут.

## Состав проекта

- `src/ui/` — интерфейс и карта.
- `src/core/` — алгоритмы, проверка каталога, запросы и экспорт.
- `data/places_catalog_full.json` — каталог мест.
- `configs/experiments.json` — параметры исследования и версия протокола, которая используется в JSON-экспорте приложения.
- `tests/` — автоматические проверки каталога, ядра, маршрутизатора и рендера интерфейса.
- `src/experiments/` и `src/analysis/` — исследовательские скрипты; для работы приложения они не нужны.

Папки `work/`, `docs/`, `reports/`, `data/raw/` и `data/processed/` не публикуются. Локально они могут содержать текст работы, протокол, архив расчётов, сводки и материалы оформления. Исследовательские команды `experiments`, `experiments:reproduce`, `analysis`, `paper` и `audit` требуют соответствующих локальных материалов; в опубликованной версии без них эти команды не предназначены для запуска. Основные команды запуска, тестирования и сборки от этих папок не зависят.

## Ограничения

Координаты проверены автором по картам, но для парка, улицы или комплекса точка может быть условной, а не входом. Часы работы, платный вход, погода и доступность для маломобильных людей не учитываются. Скорость и время осмотра — расчётные допущения.

При сбое загрузки матрицы сравнение не строится на расстояниях по прямой. При сбое загрузки геометрии список остановок и показатели остаются доступны. Перед прогулкой необходимо проверить условия посещения объектов.

JSON-экспорт содержит сценарий, идентификаторы и отпечаток каталога, матрицу и результаты. Полный каталог с названиями и координатами хранится в проекте отдельно. Регистрация и геолокация не используются.
